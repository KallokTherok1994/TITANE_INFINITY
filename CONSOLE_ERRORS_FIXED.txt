PROBLÈME 1: Messages "SES Removing unpermitted intrinsics"
═════════════════════════════════════════════════════════════════

❌ PAS UNE ERREUR TITANE∞

  moz-extension://aa193544-2db3-4c07-a7a8-962c339fe630/

L'extension SES (Secure ECMAScript) essaie de sécuriser JavaScript
en supprimant certaines méthodes natives du navigateur.

MÉTHODES SUPPRIMÉES PAR L'EXTENSION:
  • %MapPrototype%.getOrInsert
  • %MapPrototype%.getOrInsertComputed
  • %WeakMapPrototype%.getOrInsert
  • %WeakMapPrototype%.getOrInsertComputed
  • %DatePrototype%.toTemporalInstant

SOLUTION:
─────────────────────────────────────────────────────────────────
  → Désactiver l'extension SES dans Firefox
  → Ou ignorer ces warnings (ils n'affectent pas TITANE∞)

PROBLÈME 2: "disallowed MIME type (text/html)" pour modules JS
═════════════════════════════════════════════════════════════════

✅ CORRIGÉ

CAUSE:
  La configuration vite.config.ts forçait tous les fichiers à avoir
  le Content-Type "text/html", y compris les modules JavaScript.

ERREUR AVANT:
  Loading module from "https://.../src/main.tsx" was blocked
  because of a disallowed MIME type ("text/html").

CORRECTION APPLIQUÉE:
  Fichier: vite.config.ts (ligne 76)
  
  AVANT:
  ─────
  headers: {
    'Content-Type': 'text/html; charset=utf-8',  ← INCORRECT
    'X-Content-Type-Options': 'nosniff',
    'X-Frame-Options': 'SAMEORIGIN',
  }

  APRÈS:
  ─────
  headers: {
    // Vite gère automatiquement Content-Type selon l'extension
    'X-Content-Type-Options': 'nosniff',
    'X-Frame-Options': 'SAMEORIGIN',
  }

MIME TYPES MAINTENANT:
─────────────────────────────────────────────────────────────────
  ✅ index.html          → text/html
  ✅ src/main.tsx        → text/javascript
  ✅ /@vite/client       → text/html (normal, module interne Vite)
  ✅ src/AppMinimal.tsx  → text/javascript
