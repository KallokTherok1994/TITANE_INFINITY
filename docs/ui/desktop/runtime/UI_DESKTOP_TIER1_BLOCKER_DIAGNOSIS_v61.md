## Root Cause: NO_TAURI_INVOKE in WDIO Browser Context

All 4 Tier 1 below-target modules produced `NO_TAURI_INVOKE` error in v60 when IPC probes were attempted via `browser.execute(() => window.__TAURI__.invoke(...))`. This is caused by a fundamental architectural constraint:

- **WDIO tests with `TITANE_ENFORCE_BINARY_FRESHNESS=0`** run in a Chrome/WebKit browser context
- **The Tauri IPC bridge** (`window.__TAURI__`) is NOT injected in this browser-only mode
- **All `window.__TAURI__.invoke()` calls** fail with `NO_TAURI_INVOKE` — not a backend error, but a test context constraint

### Why TITANE_ENFORCE_BINARY_FRESHNESS=0 is Used

This flag allows WDIO tests to run without waiting for a full Tauri binary recompile. It is the standard test context for E2E UI probes. The IPC bridge is only available when the full Tauri runtime is launched with tauri-driver pointing to a compiled binary.

## v61 Strategy: UI Evidence Capture

### Rationale

Since Tauri IPC is not available in the WDIO browser context, v61 switches to direct DOM-based evidence capture:

1. **Navigate to the module route**
2. **Check for ErrorBoundary** (confirms page didn't crash)
3. **Probe UI elements** using `data-testid` selectors
4. **Capture text evidence** (redacted for security)
5. **Classify honestly**:
   - UI found → `DEGRADED_WITH_UI_PROOF` (renders but IPC not confirmed)
   - UI found + governed → `GUARDED_WITH_UI_PROOF` (renders + governance confirmed)
   - UI not found → stays at previous level
